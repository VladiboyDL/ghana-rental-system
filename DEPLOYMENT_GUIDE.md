# Ghana Rental System - Deployment Guide

## Overview

This guide covers deploying:
1. **Backend API** + **PostgreSQL Database** + **Web Dashboard** to Render
2. **Mobile App** to TestFlight (iOS) and Play Store (Android)

---

## Part 1: Render Deployment (Backend + Database + Web Dashboard)

### Prerequisites
- Render account (https://render.com)
- GitHub repository with the code pushed

### Step 1: Connect GitHub to Render

1. Go to https://dashboard.render.com
2. Click **New** > **Blueprint**
3. Connect your GitHub account
4. Select this repository
5. Render will detect the `render.yaml` file automatically

### Step 2: Configure Environment Variables

Before deploying, set these in Render Dashboard:

| Variable | Description | Where to Set |
|----------|-------------|--------------|
| `AWS_ACCESS_KEY_ID` | AWS S3 access key (for file uploads) | ghana-rental-api service |
| `AWS_SECRET_ACCESS_KEY` | AWS S3 secret key | ghana-rental-api service |

**Auto-generated by Render:**
- `DATABASE_URL` - PostgreSQL connection string
- `JWT_SECRET` - Auto-generated secure secret

### Step 3: Deploy

1. Click **Apply** on the Blueprint
2. Render will create:
   - `ghana-rental-api` - Backend API (Node.js)
   - `ghana-rental-dashboard` - Web Dashboard (Static site)
   - `ghana-rental-db` - PostgreSQL Database

3. Wait for deployment (usually 5-10 minutes)

### Step 4: Verify Deployment

1. **API Health Check**: Visit `https://ghana-rental-api.onrender.com/api/health`
   - Should return: `{"success":true,"data":{"status":"healthy",...}}`

2. **Web Dashboard**: Visit `https://ghana-rental-dashboard.onrender.com`
   - Should show login page

### Step 5: Initialize Database (First Time Only)

If you need to seed demo data, connect to Render Shell:

```bash
# In Render Dashboard > ghana-rental-api > Shell
npm run seed
```

### Render URLs After Deployment

| Service | URL |
|---------|-----|
| API | https://ghana-rental-api.onrender.com |
| Dashboard | https://ghana-rental-dashboard.onrender.com |
| Database | Internal (auto-configured) |

## Part 2: Mobile App Deployment (TestFlight)

### Prerequisites

1. **Apple Developer Account** ($99/year) - https://developer.apple.com
2. **Expo Account** (free) - https://expo.dev
3. **EAS CLI** installed: `npm install -g eas-cli`

### Step 1: Configure EAS

```bash
cd mobile

# Login to Expo
eas login

# Initialize EAS project (first time only)
eas init

# This will give you a project ID - update app.config.js with it
```

### Step 2: Update Configuration

Edit `mobile/eas.json` and replace placeholders:

```json
{
  "submit": {
    "production": {
      "ios": {
        "appleId": "your-apple-id@email.com",      // Your Apple ID
        "ascAppId": "123456789",                    // App Store Connect App ID
        "appleTeamId": "XXXXXXXXXX"                 // Your Apple Team ID
      }
    }
  }
}
```

**Finding your Apple Team ID:**
1. Go to https://developer.apple.com/account
2. Look for "Team ID" in Membership section

**Finding App Store Connect App ID:**
1. Go to https://appstoreconnect.apple.com
2. Create new app (if not exists)
3. App ID is in the URL or App Information

### Step 3: Build for TestFlight

```bash
cd mobile

# Build iOS app for App Store / TestFlight
eas build --platform ios --profile production
```

This will:
- Build the app in Expo's cloud
- Generate an `.ipa` file
- Handle code signing automatically (or prompt for credentials)

**First time:** EAS will ask you to:
1. Log in to Apple Developer account
2. Select/create certificates
3. Select/create provisioning profiles

### Step 4: Submit to TestFlight

```bash
# Submit the build to TestFlight
eas submit --platform ios --profile production
```

Or submit automatically after build:
```bash
eas build --platform ios --profile production --auto-submit
```

### Step 5: TestFlight Configuration

1. Go to https://appstoreconnect.apple.com
2. Select your app > TestFlight
3. The build will appear after processing (15-30 minutes)
4. Add test information and export compliance
5. Add internal/external testers

### TestFlight Testing Groups

**Internal Testers** (up to 100):
- App Store Connect users in your team
- Builds available immediately

**External Testers** (up to 10,000):
- Anyone with email address
- Requires Beta App Review (1-2 days)

## Part 3: Android Deployment (Play Store)

### Prerequisites

1. **Google Play Developer Account** ($25 one-time) - https://play.google.com/console
2. **Google Cloud Service Account** with Play Developer API access

### Step 1: Create Service Account

1. Go to Google Play Console > Setup > API access
2. Create new service account
3. Grant "Release to production" permission
4. Download JSON key file

### Step 2: Configure EAS

Place the JSON key file in the mobile folder and update `eas.json`:

```json
{
  "submit": {
    "production": {
      "android": {
        "serviceAccountKeyPath": "./google-play-key.json",
        "track": "internal"
      }
    }
  }
}
```

### Step 3: Build and Submit

```bash
cd mobile

# Build Android app bundle
eas build --platform android --profile production

# Submit to Play Store
eas submit --platform android --profile production
```

## Troubleshooting

### Render Issues

**Build fails:**
- Check build logs in Render Dashboard
- Ensure all dependencies are in package.json
- Check Node.js version compatibility

**Database connection issues:**
- DATABASE_URL should be auto-configured
- Check SSL settings in database.js

**API returns 404:**
- Verify health check at `/api/health`
- Check route configuration in routes/index.js

### TestFlight Issues

**Build fails:**
- Run `eas build --platform ios --profile production --clear-cache`
- Check app.config.js for errors
- Verify bundle identifier matches Apple Developer

**Submission fails:**
- Verify Apple credentials in eas.json
- Check App Store Connect app exists
- Ensure proper signing certificates

**"Missing Compliance" in TestFlight:**
- Go to TestFlight > your build
- Answer export compliance questions
- Usually select "No" for encryption if using standard HTTPS
